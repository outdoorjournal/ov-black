# Knowledge

Non-obvious lessons learned while building this project. Only entries that would save a future agent investigation time belong here — skip anything already covered by code, commit history, or DECISIONS.md.

## Supabase + SQLAlchemy

- **Never emit `CREATE TYPE` from SQLAlchemy when the migration owns DDL.** Use `SAEnum(..., create_type=False, native_enum=True)` so the ORM binds string values but never tries to re-create the enum. Combine with `values_callable=lambda e: [m.value for m in e]` so asyncpg sees the literal string values (`'advisor'`), not Python enum member names. (D003 / T04)
- **Always declare `DateTime(timezone=True)` on timestamp columns.** Without it, SQLAlchemy's default is tz-naive TIMESTAMP, and asyncpg renders UPDATE statements as `TIMESTAMP WITHOUT TIME ZONE`, which then rejects tz-aware Python datetimes. The bug only surfaces on the UPDATE path (inserts fill from server defaults), so it hides until you try to update `consumed_at` or similar. (T04)
- **pytest-asyncio 0.24 runs each test in its own event loop.** Use a function-scoped engine fixture, not module/session — asyncpg connections are loop-bound and a module-scoped engine will produce `Event loop is closed` / "attached to a different loop" errors. Cheap against local Postgres. (T04)
- **RLS-enabled + zero policies = deny-by-default for anon/authenticated, bypass for service_role.** That is the correct contract for tables the application only ever touches via the admin/service path. Don't add a redundant `service_role` policy — a future reviewer may copy it with `to authenticated` and blow a hole open. (T04, invites table)
- **Don't model FKs to `auth.users` with SQLAlchemy `ForeignKey(...)`.** The `auth` schema isn't part of our declarative metadata, so SQLAlchemy raises `Foreign key ... could not find table 'auth.users'` at flush time. The DB still enforces the reference via the migration — leave the model column bare (typed `UUID(as_uuid=True)` only), matching Profile/Invite. (T02/S03)

## Supabase SSR (Next.js)

- **Use `supabase.auth.getUser()`, never `getSession()`, for server-side auth gates.** `getUser()` revalidates the JWT against Supabase's server; `getSession()` trusts the cookie contents, so an attacker with a forged cookie walks past a `getSession`-based gate. (D016 in task notes, T06)
- **Magic-link callbacks must handle both shapes.** @supabase/ssr 0.10+ defaults to PKCE (`?code=...`), but older email templates still send `?token_hash=...&type=magiclink`. Handle both to avoid a user clicking a valid link and landing on a broken page during a template rollover. (T06)
- **@supabase/ssr 0.10+ cookie adapter takes `getAll`/`setAll`, not the old `get`/`set`/`remove` trio.** Swallow write errors from `setAll` inside RSC render paths — RSCs can't mutate cookies; route handlers and middleware are the write paths. (T06)

## FastAPI auth middleware

- **Enforce "global except whitelist" via a `BaseHTTPMiddleware` with a path whitelist rather than per-route `Depends`.** The middleware is the single chokepoint for R017 (every endpoint requires a validated JWT); auditing a middleware is cheaper than grepping every future router for `Depends(require_user)`. Whitelist `/health`, `/openapi.json`, `/docs`, `/docs/oauth2-redirect`, `/redoc`, plus the tiny set of unauthenticated entry points (e.g. `/auth/redeem-invite`). (T03)
- **Supabase JWTs do not carry a consistent `aud` claim across projects, but always carry `iss`/`sub`/`exp`.** Use PyJWT's `require=['exp','iat','sub']` with `verify_aud=False`. (T03)
- **JWKS cache: TTL + kid-miss refresh, not background refresher.** In-process, synchronous httpx — the cache is populated from the middleware's decode path, so async-through adds no real latency benefit at key-rotation frequencies. (T03)
- **Emit stable, machine-readable rejection reason codes on 401 bodies** (`missing_authorization_header`, `token_expired`, `wrong_issuer`, `unknown_signing_key`, ...) — gives tests deterministic assertions and future CloudWatch dashboards something to group on. Never log the token itself. (T03)

## AWS CDK

- **Prefer `Vpc.fromVpcAttributes` over `Vpc.fromLookup` when the VPC is out-of-repo.** `fromLookup` needs live AWS credentials at synth time, breaking hermetic `cdk synth` from CI and clean checkouts. `fromVpcAttributes` with per-env CDK context + dummy fallbacks keeps synth deterministic without credentials; real operators still fail fast at CloudFormation if they forget to populate vpcId/subnets. (D018 / T08)
- **CDK's `ts-node --prefer-ts-exts` entry cannot consume NodeNext + `verbatimModuleSyntax` + `isolatedModules` without resolver errors.** `infra/cdk/tsconfig.json` must NOT extend `tsconfig.base.json` — keep it self-contained with `module: commonjs`, `moduleResolution: node`. Other strictness flags (strict, noImplicitReturns, noFallthroughCasesInSwitch) still apply. (D019 / T08)
- **Give containers BOTH the secret ARN (plain envvar) and the secret value (ECS `secrets:` native injection).** Lets the app pick SDK-side fetch or env-injection without another infra round-trip. (T08)
- **Env-aware RemovalPolicy: staging = DESTROY, prod = RETAIN on secrets/ECR/log groups.** Prevents a `cdk destroy` mishap from nuking credentials or audit logs in prod. (T08)

## Monorepo / Turborepo

- **apps/api is NOT a pnpm workspace member (no package.json).** Turbo can't orchestrate it. Split Python pytest into its own CI job rather than shoehorning it into Turbo; keep caches independent. (T09)
- **Regeneration of `packages/api-client/src/generated/` is gitignored — consumers must run `pnpm turbo run generate` before `pnpm turbo run build` on a fresh checkout.** CI (and any deploy pipeline) must sequence install → generate → build. (T07, T09)
- **Turbo `^build` dependency chain handles cross-workspace ordering for free** once `@ov-black/api-client` is listed as a workspace dep on `apps/web`. Don't hand-script the order. (T07)
- **apps/web tsconfig must override `verbatimModuleSyntax: false`** — Next's compiler breaks default interop for client components when it's on. Keep every other strictness flag from `tsconfig.base.json`. (T06)

## Invite redemption / security

- **DB-atomic consume via `UPDATE ... WHERE consumed_at IS NULL RETURNING code`.** Empty RETURNING maps to already-consumed; this is how you avoid the SELECT-then-UPDATE TOCTOU gap that would let concurrent requests double-redeem. Roll back on upstream Supabase failure so the invite stays redeemable across transient hiccups. (D014 / T05)
- **Collapse unknown-code and wrong-email into the same 404 `invite_not_redeemable`** — distinct responses let an attacker enumerate which codes exist by probing with any email. Already-consumed can safely use its own 409 because the info leak is symmetric (the legitimate holder already knows). (D015 / T05)

## apps/web forms (react-hook-form + zod + shadcn)

- **Type `useForm` with `<z.input<schema>, unknown, z.output<schema>>`, not `<z.infer<schema>>`.** Under this repo's `exactOptionalPropertyTypes: true`, any zod `.default(...)` field has input type `string | undefined` and output type `string`. Passing a single `z.infer` (the output) to `useForm` makes `ResolverOptions<input>` diverge from the useForm generic, which then collapses `handleSubmit`'s callback param to bare `FieldValues` with a cryptic "missing properties" error. The two-type shape keeps the form type-safe end to end. (T07/S03)
- **shadcn's `FormField` wrapper needs a third `TTransformedValues` generic on `react-hook-form@7.72+` / `@hookform/resolvers@5+`.** The default shadcn-CLI output only forwards `<TFieldValues, TName>`; the new `ControllerProps` carries `<..., TTransformedValues = TFieldValues>`, and `useForm` with a zodResolver types `Control` with a non-default `TTransformedValues`, so `control={form.control}` no longer unifies. Add the third generic (default = `TFieldValues`) to FormField and the zodResolver + legacy call-sites both compile. (T07/S03)
- **`createApiClient({ accessToken })` cannot accept `accessToken: string | undefined`.** `ApiClientConfig.accessToken` is declared plain-optional, which under `exactOptionalPropertyTypes` rejects `undefined`. Build the arg with a ternary (`accessToken ? { baseUrl, accessToken } : { baseUrl }`) at the callsite rather than widening the config type — widening would force the unauthenticated redeem-invite flow to pass `undefined` explicitly and breaks the T06 interceptor contract. (T07/S03)
- **shadcn CLI `init` is interactive — hand-author the state under auto-mode.** Write `components.json`, `lib/utils.ts` (the `cn` helper), the tailwind config extension (CSS-variable color tokens + `tailwindcss-animate`), and the CSS `:root` variable block. The seven primitives (button/card/form/input/label/select/textarea) can be authored byte-identical to shadcn new-york output, so a later `shadcn add` sits on top without drift. Keep Tailwind v3 — S01 depends on it. (T07/S03)

## TestClient + asyncpg integration tests

- **Never share an asyncpg engine between `TestClient` and the test thread.** `fastapi.testclient.TestClient` runs the app via anyio's portal on its own loop; an engine you create in your test fixture lives on a different loop, and any DB call you make from the test directly will fail with `Future ... attached to a different loop` or `Event loop is closed`. Two safe shapes: (a) create the engine **inside** the `get_session` dependency so SQLAlchemy binds connections to whatever loop the request handler is running, and (b) for assertions/cleanup that need to read from the DB outside an HTTP call, use `asyncio.run()` with a fresh per-call engine. The connection-setup overhead is negligible against local Postgres. (T07)
- **JWT `sub` round-trips into `created_by` FK on `itineraries` (and similar tables).** The router parses `user.sub` as a UUID and threads it as `user_id`; if the UUID happens to look real but isn't a row in `auth.users`, the insert hits a foreign-key violation. For DB integration tests that don't bother provisioning an `auth.users` row, mint the JWT with a non-UUID sub (e.g. `"s02-acceptance-actor"`) so the router falls back to `user_id=None` while still recording `actor_id` on every history row. (T07)
- **`get_sessionmaker()` is `lru_cache`-bound to the loop that first touches it.** Under `TestClient` this triggers asyncpg `Future attached to a different loop` crashes the first time a router handler queries. Monkey-patch the module-level `get_sessionmaker` symbol per-call to build a fresh `async_sessionmaker` per request (leaks engines until GC — acceptable for tests). Same pattern as the S02 slice acceptance. (S04/T06)

## FastAPI + SSE (streaming responses)

- **Routers that read singletons via `request.app.state.X` cannot be test-injected with `dependency_overrides[get_X]`.** If the router does `runtime = request.app.state.agent_runtime` (not `runtime: AgentRuntimeClient = Depends(get_agent_runtime)`), then `app.dependency_overrides[get_agent_runtime] = ...` is a silent no-op — the lifespan-installed mock keeps firing. Install a proxy on `app.state.agent_runtime` directly and have tests arm/disarm it. Production code stays untouched. (S04/T06)
- **Disable proxy buffering on SSE with `X-Accel-Buffering: no` AND `Cache-Control: no-cache`.** Without both, nginx (or CloudFront) can buffer the entire stream and defeat the `first_token < 2s` bar. ALB idle timeout also matters — set it at the `ApplicationLoadBalancer` constructor (`idleTimeout: Duration.seconds(120)`), not at `addListener()` which doesn't accept the prop in CDK v2.250. (S04/T05+T07)
- **Do not hold a DB transaction across an upstream SSE stream.** Session A writes the user turn, commits, closes; retry envelope runs outside any transaction; session B writes the assistant (or error) turn post-stream. Holding a transaction across the wire wedges the connection pool and turns every upstream hiccup into a lock wait. (S04/T04)
- **Retry only before first byte.** Once any SSE byte is emitted downstream, never retry — duplicate-delta on a recovering upstream would break the client's parser. Failures past the first byte land as a `role='error'` turn row + a crafted fallback SSE frame so the failure is both user-visible and permanently auditable. (S04/T04)

## boto3 in async FastAPI

- **Wrap sync boto3 calls in `anyio.to_thread.run_sync` to keep the event loop unblocked.** The `bedrock-agentcore` client's `invoke_agent_runtime` returns a response body whose `iter_lines()` generator is sync; wrap both the initial call AND the per-line iteration in thread offloading so a slow upstream never starves other requests. (S04/T03)
- **Disable boto3's internal retry layer (`retries={'mode':'adaptive', 'max_attempts':1}`) when you own retry at the service layer.** Otherwise boto3 retries silently, your service-layer retry retries again, and an upstream throttle turns into 4× the delay with no `agent.turn.retry` log to show for it. (S04/T03)
- **Construct the boto3 client lazily (inside `invoke_stream`, not in `__init__`).** Tests should never need AWS credentials to import or instantiate the wrapper; lazy construction means `_client is None` is assertable in unit tests and the real client only materializes on the first real call. (S04/T03)
- **Map any botocore exception to a single domain exception `AgentRuntimeError(reason=<ExceptionClassName>)` rather than enumerating specific botocore types.** The reason string (`ThrottlingException`, `ServiceUnavailableException`, ...) is stable enough for the service-layer retry envelope to switch on without coupling to botocore internals. (S04/T03)

## JIT auth backfill (S05)

- **Fail-closed cross-schema reads for JIT auth backfills.** When a service path needs to read `auth.users` to backfill a `clients.auth_user_id`, wrap the SELECT + UPDATE in a single try/except SQLAlchemyError that returns `False` on ANY failure (permission denial, NULL row, email mismatch). The caller falls through to the existing FORBIDDEN/404 branch — the request never crashes and the auth grid stays consistent. The Postgres `authenticated` role inherits the necessary `auth.users` read via Supabase's GRANT chain (verified in 0001_init.sql), so no new GRANT is needed in steady state — the fail-closed wrapper is the safety net for grant drift. (S05/T01)
- **`ON CONFLICT (id) DO NOTHING` for `public.profiles` upserts in any code path that doesn't own role assignment.** The clause makes downgrading a pre-existing `role='advisor'` row structurally impossible from the JIT-client path. Don't use `DO UPDATE SET role='client'` even though that path doesn't intersect with advisor traffic today — refactors are cheap to write and dangerous to misread. (S05/T02)
- **Inline `_enforce_client_access` into `open_or_reuse_session` rather than mutating the helper signature.** The helper is reused by `list_turns`, which must stay strict against the un-backfilled row. Inlining lets the session-open path see the freshly-backfilled `auth_user_id` in memory without a second SELECT, while keeping the read-path unchanged. (S05/T01)

## Next.js auth callback (S05)

- **Tighten `?next=...` short-circuit to ONLY honor an explicitly-provided same-origin path.** The previous code defaulted `next` to `/command-center` when absent, which would have silently bypassed any role-aware redirect. Make the override path explicit so role resolution is the default and `?next=...` is a deliberate operator escape hatch. (S05/T03)
- **Treat 'missing profile row' as `'unknown'`, NOT as a default `'client'`.** Lets the callback distinguish "no profile yet" from "real client whose clients row is resolvable." Missing-profile users still fall through to the `clients.auth_user_id` lookup (the load-bearing branch for freshly-magic-linked invitees), but keeping the role enum tight (advisor|client|unknown) lets future code make decisions on the absence rather than misinterpreting a default. Use `.maybeSingle()` (not `.single()`) so the zero-row case returns `data=null` without throwing. (S05/T03)

## DIY SSE consumer in the browser (S05)

- **Never throw from the SSE frame parser.** Malformed JSON and unknown frame types should `console.warn` (with a truncated excerpt — never the full payload, never any content) and skip. The hook above can then assume `parseFrames` is total: it returns frames + remaining and never blows up the read loop. Carry-buffer the trailing fragment across `getReader()` reads so deltas split mid-frame still parse on the next read. (S05/T04)
- **Hold hook options behind a ref so `sendTurn`'s identity is stable.** Per-render callback swaps would otherwise cause delta frames arriving mid-render to fire into stale closures. The `abortRef` should be caller-owned (a `MutableRefObject` passed in) — keeps the hook stateless for StrictMode double-invoke safety and lets the composer + unmount effect share a single abort handle. (S05/T04)
- **AbortError from `fetch()` is silent; non-2xx and network errors map to the SAME error frame the backend emits.** Don't surface AbortError via `onError` — the abort is always caller-initiated (composer cancel, unmount). For transport failures, dispatch `{type:'error', reason:'upstream_unavailable'}` — identical to the backend's S04 fallback shape — so the UI handles one error path regardless of where the failure originated. (S05/T04)
- **The agent's "opening move" needs a bootstrap turn because S04's content validator requires `1..8000` chars.** A single space (`' '`) is the minimal craft-feel nudge that lets the agent open the correspondence without the user typing first. Document the constant inline (BOOTSTRAP_CONTENT) and `useRef`-guard the trigger so it fires exactly once on mount when `initialTurns.length === 0`. Suppress the optimistic user-row render for this synthetic turn — the user shouldn't see a blank message in their own column. (S05/T05)

## vitest test runner (apps/web)

- **`vitest -t '<name>'` is a regex AND a no-match exits 0 ("0 ran, 0 failed" → green).** Naming tests `(N) ...` and filtering with `-t '(N)'` will treat the parens as an empty regex group and silently green-wash every check. Pick parenthesis-free substrings unique to each test, AND assert `numPassedTests >= 1 && numFailedTests == 0` from the JSON reporter (parsed via `JSON.parse(fs.readFileSync(...))`, not `require()` which rejects non-`.json` paths). (S05/T06)
- **Set `esbuild.jsx: 'automatic'` in `vitest.config.ts` for React 19 + Next 15.** Next's tsconfig keeps `jsx: preserve` (SWC consumes it) — vitest's esbuild path needs its own directive or every `.tsx` test file would need an explicit `import React`. Mirror the `@/*` path alias into `resolve.alias` so test imports match app conventions. (S05/T06)
- **Register `afterEach(cleanup)` in `tests/setup.ts` when vitest `globals: false`.** RTL's auto-clean only registers itself when `afterEach` is a global; without globals, a second `render()` stacks a second `<main>` into `document.body` and assertions fail with "multiple elements found." (S05/T06)

## Atmospheric morph (S06)

- **Hold phase-shift state in `useRef`, not `useState`, and compute the tick during render with a length-based guard.** React 19 StrictMode double-invokes component bodies in dev; `useState` increments would double-tick the phase counter and make the per-3-turns gate behave like a per-6-turns gate in dev only. A `lastTickAtLengthRef` short-circuits the second StrictMode call because `turns.length` has not advanced between the two invocations. `useEffect` works too but is unnecessary — the tick is pure derivation from `turns.length`, so it belongs in render. (S06/T02)
- **`next/image` with `alt=""` is not reliably findable via `screen.getByAltText('')` in jsdom.** Scope by the known data-attribute wrapper (`imageLayer.querySelector('img')` where `imageLayer = [data-atmos-layer="image"]`) when you need to trigger `fireEvent.error(img)` in a test. Bullet 6 of `s06-slice-acceptance.test.tsx` uses this pattern. (S06/T04)
- **Use hex palettes (not HSL) for any registry whose contrast math is test-asserted.** The inline-style consumption is identical (`backgroundColor: '#rrggbb'`), but a hex-only WCAG `contrastRatio` helper fits in 15 LOC; an HSL parser doubles that and pulls in color-space conversion. The MOODS registry at `apps/web/lib/atmos/moods.ts` is hex for this reason and bullet 5 of the slice suite parses hex only. (S06/T01, S06/T04)
- **Decorative full-bleed frames must be `aria-hidden` and the `<Image>` must carry `alt=""`** — otherwise the decorative art pollutes the accessibility tree and screen readers announce "image, image, image" on every mood drift. The `#atmos-frame` wrapper is `aria-hidden`; the `<Image>` is `alt=""` with `fill` + `sizes="100vw"`. (S06/T03)
- **Key the AtmosFrame root off the `mood` prop to get clean stacked-layer crossfades.** `<div key={mood} id="atmos-frame" ...>` forces React to fully reconcile both layers on mood change so the `transition-opacity`/`transition-colors` animations do not interleave with a prior mood's `<Image>` still fading out. No manual z-index needed — DOM order keeps palette below image. (S06/T03)

## Slice verify-script chains (auto-mode gate)

- **Use `pnpm -C <dir>` instead of `cd <dir> && pnpm ...` in task `Verify:` chains.** The auto-mode verification gate splits the chain on `&&` and runs each segment as an isolated check, so `cd apps/web` succeeds but does NOT carry into the next call's cwd — `pnpm test` then runs from the repo root, where it dispatches through Turborepo and rejects `--run` as an unknown turbo flag. `pnpm -C apps/web test -- --run <suite>` is cwd-agnostic. (S05/T06 verify-fix)

## Itinerary approval gate + advisor lock (S08)

- **Keep `status` orthogonal to `locked_by`/`locked_at`.** The lock is an editor-session advisory column; status is the client-visibility gate. Decoupling them means an advisor can release mid-draft for a second editing round without flipping to approved, and re-lock later. Folding one into the other (e.g. "`locked_by IS NULL` means approved") would conflate visibility with editorship and wedge any future workflow that needs either axis independently. (S08/T01)
- **In-memory `FakeFactory`s that match `itineraries.id` SELECTs must guard specifically against `itineraries.locked_by` SELECTs once `_check_lock` lands.** Without the guard, the fake's generic `itineraries.id` branch returns the itinerary's UUID when the service asks for `locked_by`, and the lock gate trips LOCKED in tests that never meant to exercise the lock. Three agent-service tests broke for exactly this reason before the guard was added. Return `FakeResult(rows=[None])` for the `locked_by` SELECT — NULL is the right answer for fakes that don't exercise lock contention. (S08/T02)
- **Seed `auth.users` rows in lock-path tests — `itineraries.locked_by` and `approved_by` are real FKs.** A minimum-column insert (id + email + `is_sso_user=false` + `is_anonymous=false`) is ~1ms and lets the FK constraint exercise production-shape. Tear the rows down on a throwaway engine so rollback-wrecked sessions can't break teardown. Pattern mirrors the S07/T05 footgun about `itineraries.client_id → auth.users(id)` FK mismatches. (S08/T02)
- **Stash `itinerary.id` up front when a test commits multiple primitives against the same row.** SQLAlchemy's expired-attribute lazy-load tries to refresh unrelated rows after a commit, which trips the async/greenlet guard. Same idiom used in `test_itineraries.py::test_self_loop_edge_maps_to_validation_error`. (S08/T02)
- **Drain the queue from the release-lock route, not from the service function itself.** `release_lock` belongs in `services/itineraries.py` (pure DB primitive). The router handler is where `drain_queue(get_sessionmaker(), id)` runs, so the service layer stays free of session-factory coupling and the queue stays a router/composition concern. (S08/T04)
- **`get_sessionmaker()` is `lru_cache`-bound to the loop that first touches it** (already recorded for S04). For S08's release route, this means `drain_queue` takes a `session_factory` argument rather than calling `get_sessionmaker()` internally — otherwise mid-stream drain would run against the wrong loop in test harnesses. (S08/T03)
- **Pop drained queue entries before replay, not after.** `_agent_write_queue.pop(itinerary_id, [])` at drain start returns 0 from `queue_depth(itinerary_id)` immediately. A failed replay doesn't leave an orphan key behind, and the assertion `queue_depth == 0` after release is deterministic even under partial-failure paths. (S08/T03)
- **Actor promotion happens in the router, not in `require_advisor`.** The `POST /assemble` route uses `Depends(require_user)` and promotes to ADVISOR via a one-shot `_is_requester_advisor` profiles SELECT so non-advisor callers (e.g. agent-driven assembly) are legitimately admitted — the service's `_check_lock` is the final enforcement. If you swap `require_advisor` in instead, the route stops being callable from the agent-side SSE path. (S08/T04)
- **The hey-api SDK client uses `fetch(new Request(...))`** (already recorded for S07). Lock-route vitest mocks must normalize both call shapes — read `input.url`/`input.method`/`await input.clone().text()` when `input instanceof Request`, fall back to the two-arg form otherwise. (S08/T05)
- **Keep advisor-surface lock state local (React `useState`), not derived from `ItineraryResponse`.** The API response shape intentionally does not expose `locked_by` (it would leak across advisors). Infer lock state from Edit-click outcomes: success → `locked-by-me`, 409 `already_locked` → `locked-by-other`, Release success → `unlocked`. The lock state ref is purely a UI affordance — the DB is the source of truth and the `_check_lock` gate enforces it. (S08/T05)
- **`updateNode` as a sibling of `updateNodeStatus`, not a replacement.** S07's `MoodBoard` pin/keep/discard still calls the narrower status-only wrapper; S08's advisor surface needs to PATCH title + source_id together so `updateNode` accepts a broader `UpdateNodePatch`. Keep both — the narrow wrapper stays grep-able as the "status transitions only" call site. (S08/T05)
- **`pytest_plugins=('tests.test_agent_service',)` at module level is supported in pytest 8.** The deprecation warning is only for non-root `conftest.py` declarations. Module-level `pytest_plugins` in a test file is the right way to reuse ~90 lines of FakeFactory fixtures across `test_agent_service.py` / `test_agent_assemble_draft.py` without duplicating setup. (S08/T05)
- **Malformed day-plan UUIDs short-circuit BEFORE touching the service.** The `elif kind == 'assemble_draft'` branch in `stream_turn` parses each `node_id` string → `uuid.UUID` with a try/except; on failure, emit `agent.assemble_draft.malformed` INFO, forward the frame with `edges_created: 0`, and skip the service call. The advisor surface still progresses and never sees a 500 from an agent typo. (S08/T05)
- **Forward assemble_draft SSE frames with string day_plan UUIDs, not UUID objects.** `json.dumps` on `uuid.UUID` raises; the browser needs strings anyway. Pass `uuid.UUID` instances into the service layer (which requires them), but stringify before forwarding. (S08/T05)
- **S02 slice-acceptance tests used a non-UUID sub (`'s02-acceptance-actor'`) to sidestep the `auth.users` FK.** Post-S08 the draft-read gate needs `actor.user_id == created_by`, which requires a real UUID. Update the fixture to seed a real `auth.users` row with a random UUID and tear it down on teardown — each test now creates and reads as the same user. Non-UUID sub coverage stays in `test_itineraries.py::test_create_itinerary_with_non_uuid_sub_still_succeeds`. (S08/T04)

## Client final itinerary render (S09)

- **Reconstruct day chains from flat `follows` edges — do NOT depend on persisted `day_index`.** `services/itineraries.py` treats `day_index` as caller-side ordering, not durable state, so the render layer must walk heads-no-incoming-follows → walk outgoing `follows` to emit day chains. Non-`follows` edge types (`grouped_with`, `alternative_to`, ...) must be filtered out before the walk or they merge unrelated chains. First outgoing `follows` wins on accidental fan-out; orphans with no edges land in single-node days at the end in node-id sort order so nothing silently disappears. (S09/T01)
- **Client-surface RSCs collapse all non-ok `getItinerary` results to `notFound()`.** 403 forbidden, 404 itinerary_not_found, network_error — all to the same branch. The S08 API gate is the source of truth for existence-hiding on drafts; branching in the RSC would leak "you exist but cannot see me" signal to the client surface. Mirrors the advisor page collapse pattern. (S09/T03)
- **The final itinerary view does NOT need `accessToken`/`apiBaseUrl` pass-through to its client component.** Unlike the advisor draft editor (which needs them for PATCH/approve/lock calls), the final view is fully server-rendered with no client-side fetch. Passing them down would widen the attack surface for zero functional gain. (S09/T03)

## Mood-board cards + SSE pass-through (S07)

- **The `stream_turn` pass-through seam (`else: yield _sse_encode(event)`) is the right place to add new SSE frame types.** Don't write a streaming block parser or add a new code branch per frame kind — the existing unknown-kind forwarder carries `card` frames verbatim after an in-line persistence side-effect. Augment the emitted frame with a durable id (e.g. `node_id`) so the client reducer can key its state on something stable across reloads. New frame kinds must also be added to `apps/web/lib/agentStream.ts::KNOWN_FRAME_TYPES` — it's a load-bearing allowlist and forgetting to add one silently drops the frame with a `console.warn`. (S07/T02+T04)
- **`itineraries.client_id` FKs to `auth.users(id)`, not `public.clients(id)`.** Any path that creates itineraries (e.g. `_ensure_itinerary_for_client`) must be triggered by a caller who already has a matching `auth.users` row — in production the JIT auth backfill from S05/D021 populates this at first session-open. Integration fixtures that seed `public.clients` rows directly must also seed an `auth.users` row with the same id, or the INSERT will fail with a FK violation. T03 unit tests use `FakeFactory` so never hit this; T05 flipped it live by calling `_ensure_itinerary_for_client` on every `open_or_reuse_session`. Fixed in `test_s04_slice_acceptance.py` by seeding matching auth.users rows. Consider a server-side assertion or changing the FK target to `public.clients(id)` in a future slice. (S07/T05)
- **Never click pin → keep → discard on the same mounted card in a single test.** The reducer's optimistic flip changes the starting state — after `pin` lands `status=approved`, the next `keep` click fires a real PATCH (approved→proposed) instead of the optimistic-only no-op the plan intends. Use a `clickAndUnmount` helper: fresh fetch-mock per iteration, fresh mount, fire one click inside `act`, flush microtasks, unmount. Bullet 3 of `s07-slice-acceptance.test.tsx` follows this pattern. (S07/T06)
- **The hey-api SDK client wraps calls in `fetch(new Request(...))`, not `fetch(url, init)`.** A fetch mock that reads `init?.method` / `init?.body` gets `undefined` on SDK-dispatched PATCHes because the args live on a `Request` object. Normalize both shapes: if `input instanceof Request`, read `input.url` / `input.method` / `await input.clone().text()`; otherwise fall back to the two-arg form (still used by the DIY SSE consumer). (S07/T06)
- **`next/image`'s rewritten `src` URL-encodes the original loader input.** `expect(img.src).toContain(cover_image)` fails when the original has characters next/image encodes. Run `decodeURIComponent(img.src)` before the containment check — same invariant, URL-shape-agnostic. (S07/T06)
